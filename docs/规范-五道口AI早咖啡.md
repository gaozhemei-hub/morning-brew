> **这份文件是唯一依据**：每天的自动执行、将来的 skill、GitHub 开源版都从这一份长出来。改规范只改这一份。

## 0. 总纲领

**每天早上，用一杯咖啡的时间，把隔夜（美国）与昨天（中国）的 AI 及相邻行业的信息，按三层结构严格筛过一遍，写成一份可以发邮件、也可以进 Obsidian 的晨报。**

四条铁律：
1. **人设代入**：每层由一个明确的专业身份来读（见各层）。不是"小编摘要"，是**那个人早晨会怎么看**。
2. **严谨规范**：每条必须带**链接 + 时间**；查不到就写"未找到"；**不编造、不推测成结论**。
3. **分级**：每条给"必须知道 / 值得知道 / 可忽略"三级。
4. **先长后精**：早期允许写长（信息密度优先），用户改过几轮后再压缩到"一针见血"。**不要一开始就为了短而砍信息。**

**产出两个出口**（同一份内容）：
- **Obsidian**：`01-五道口AI早咖啡/五道口AI早咖啡-<YYYY-MM>.md`（按月累积，同一天不重复追加）
- **邮件**：发到用户邮箱（通道待定，见 §6）

## 1. 第一层｜商业与战略层（看"钱"和"壁垒"）

**人设**：一位看 AI 及相邻行业的**资深一级/二级市场投资人**。每天早晨第一件事是边喝咖啡边看隔夜美股、再看昨天一天的中国新闻。他要的是**最新鲜的趋势洞察**，以及关于**优秀商业模式、好赛道、好项目、好团队的非共识认知**。

**这一层真正要回答的三个问题**：
1. 为什么这个技术**能赚钱**？**谁在买单**？
2. 知名大企业、最前沿独角兽的**产品矩阵与商业布局**在怎么变？
3. 最前沿的投资机构**正在关注什么方向**？（赛道地图）

**每天必检信源**（分组管理，见 `sources.json`）：

| 组 | 信源 |
| --- | --- |
| **VC 视角** | a16z、Sequoia（红杉）、Benchmark — 重点是他们的博客与"赛道地图"（常在技术爆发前夜发布） |
| **科技圈视角** | Techmeme、X（Twitter）技术圈 |
| **创始人视角** | Y Combinator、Lex Fridman Podcast、Latent Space |
| **中文创投/商业媒体** | 量子位、机器之心、36氪、投中网、投资界、晚点 LatePost、远川研究所/饭统戴老板、深响、红杉汇、经纬创投、甲子光年、DeepTech 深科技、极客公园、雷锋网、钛媒体、IT之家、第一财经、**Granite Asia（原 GGV）** |
| **微信公众号**（2026-10-12 打通） | **硅星人Pro、42章经、饭统戴老板**（经由 BestBlogs 公开的 wechat2rss 实例；同实例还提供 **375** 个公众号，候补见《候补信源》） |

> **微信生态曾是死结**：公众号无公开接口、RSSHub 路由被下架、自建要每 80 小时扫码。
> **解决办法是抄现成的**——`ginobefun/BestBlogs` 公开维护了一个 wechat2rss 实例（375 个源，直连可用）。
> 仍缺：东四十条资本、融了么（实例未收录）。**遇到"做不到"的结论，先去 GitHub 搜有没有人做过了。**

**方法**：
- **每一篇都给摘要**，分点列出**核心观点**（不是一句话带过）。
- 出现的专业名词（如 MCP）→ 用 Obsidian 双链指向《技术名词库》，**点击可跳转**：`[[技术名词库#MCP|MCP]]`。
- 出现的大佬 → 双链指向《大佬履历卡》：`[[大佬履历卡#Jensen Huang|黄仁勋]]`。
- 当天首次出现的人物（**公司高管 / 投资人 / 核心研究者**才建卡；**媒体人、纯转发者不建**）→ 建卡 + 进"该关注的人"清单。

## 2. 第二层｜技术与前沿层（看"可能性"和"边界"）

**人设**：一位**有 AI 技术背景的 AI 产品经理**。他要知道：现在有什么新产品、产品多了什么新功能；**同行在怎么构建评测集、用什么维度衡量好坏**（准确率 / 安全性 / 长文本 / 成本 / 延迟……）。

**这一层真正要回答的问题**：
1. 有什么新产品、新功能？
2. 模型**能做什么、不能做什么**？
3. **下个月可能发生什么**？
4. 延伸出来的**盈利模式问题**（也放这一层）。

**信息源**：
- **Hugging Face Daily Papers** — 每天浏览高赞论文的 Abstract。**不需要读懂公式，只需要读懂 Task（解决了什么问题）和 Result（比以前好了多少）。**
- **X 技术圈** — 关注 AI 科学家（Karpathy、LeCun、Yi Tay 等）。技术突破往往最先在这里通过"吐槽"或"炫耀"发出来。
- **Product Hunt** — 日榜/月榜，看有哪些脱颖而出的产品。
- **Techmeme** — 每天发布什么新产品。

**方法**：同第一层——每篇给摘要、分点核心观点；专业名词双链到《技术名词库》。
**额外强调**：**评测维度**要单独成句写出来（"这件事怎么被衡量"），因为这是用户求职 AI 产品岗最需要的能力标签。

## 3. 第三层｜开源与工程层（看"实现路径"）

**目标**：看别人怎么把"论文"变成"代码"。

**内容**：
- **GitHub Trending（Python 榜）**——**每周看一次**（不必每天）。
- **LangChain / LlamaIndex 官方文档**——**每周看一次**；它们的文档更新代表业界对 **Agent 编排**的最新共识。

**★ 这一层单独做成一个子 skill**：
- 日常晨报里只给"一句话 + 链接"；
- 用户看完晨报后**有技术问题可单独调用这个 skill**深入；
- 典型用法：**遇到一个新赛道（例如 AI 视频）→ 先去 GitHub 搜 star 最多的开源项目 → 读它的 `README.md` 和**架构图**（Architecture Diagram）。

| 周几 | 轮换组 | 源数 |
| --- | --- | --- |

## 3.6 第四块｜今日中文热议（2026-10-12 用户定：加）

用 newsnow 公开 API 拉热榜（`scripts/hotlist.py`，直连可用、无需 key）：
**财联社电报 · 华尔街见闻 · 雪球热股 · Hacker News · V2EX · 少数派 · 微博热搜 · 知乎热榜**。

**写法**：只给榜单前几条，**不做解读、不评论**，并注明"反映共识温度，不是事实"。
**理由**：这一块对应陈大鹏讲的"社会共识"——**热搜是共识的体温计**，它不告诉你真相，但告诉你大家在讨论什么。

## 4. 输出规范（Obsidian）

**文件**：`01-五道口AI早咖啡/五道口AI早咖啡-<YYYY-MM>.md`，每天追加 `## <YYYY-MM-DD>（周几）` 一节；同日不重复。

**每条的格式**：
```
**<一句话判断，结论在前>**  `[必须知道]`
- **核心观点**：分点 1；分点 2；分点 3
- **为什么现在**：1–2 句，写到二阶影响
- **衡量方式**（技术层必填）：这件事用什么指标/评测集被衡量
- **名词**：[[技术名词库#MoE|MoE]] ｜ **人物**：[[大佬履历卡#Jensen Huang|黄仁勋]]
- 来源：<链接>（<日期>）
```

**双链显示规范**：链接的**显示名后面加 `↗`**（如 `MoE↗`），让"能点的东西"一眼可辨；文案末尾附**本期双链索引**，集中列出可点击入口。**这两样是为解决"看不出哪里能跳"的问题。**

**人物卡的关注入口（2026-10-12 升级：从"搜索链接"升级为"真主页"）**：每张卡最后一行必须有 `- **关注入口**：LinkedIn → <主页或搜索链接> ｜ 搜索兜底 → <搜索链接>`。

做法（见 skill `person-follow-links`）：用 `web_search` 跑 `site:linkedin.com/in "姓名" "公司"`，再用 `./scripts/linkedin_match.py` 打分：
- **机构名出现在摘要里 +3**（消歧的关键证据）
- **slug 就是姓名 +2**（如 `yann-lecun`）
- **搜索首条 +1**
- **slug 与姓名无关 −3**

≥4 → **高**（直接写个人主页）｜=3 → **中**（写主页并标「待核」）｜<3 → **低**（**只给搜索链接**，写清低分原因）。
**宁缺勿错**：实测 12 人里 10 人判高/中（含 `jenhsunhuang`、`boxaaron`、`amjadmasad`、`martincasado` 这些真 handle），2 人（Karpathy、Brockman）因证据不足被判低、只给搜索链接——**这个拒绝是对的，不要为了"看起来完整"硬塞。**
X 方面：**核实过的 handle 用主页**，未核实的一律搜索链接。**绝不自动关注**（封号风险，且那是用户自己的动作）。

**每期结构**：三层正文 → **第四块·今日中文热议** → 三件套（下）→ 双链索引。

**每天必附三件套**：
1. **该关注的人 + 直达链接**（X / LinkedIn），供用户自己点关注（一次一分钟）；
2. **今日建议深挖 1 条**（说明理由）；
3. **信源健康**一行（哪些源今天抓失败，别静默失败）。

## 5. 质量红线

- ❌ 不编造、不把推测写成结论；数字必须带出处与日期。
- ❌ 不静默失败：源挂了要写明，不能当作"今天没新闻"。
- ❌ 不改《技术名词库》《大佬履历卡》的**标题锚点**（会让历史双链失效）。
- ✅ 冲突并列不合并；查不到写"未找到"。

## 6. 邮件通道

**已定：走 SMTP 发信，发件通道可切换**。脚本：`./scripts/send_digest.py`。

⚠️ **2026-10-12 实测：Gmail 连接器在用户环境里不存在**（`manage_connections status` 查 `gmail` 返回空列表，47 个可选连接器里也没有）——所以那张授权卡点不出东西，不是操作问题。**改用 SMTP。**

| provider | 说明 | 是否可用 |
| --- | --- | --- |
| `qq`（**当前默认**） | `smtp.qq.com:465`，需在 QQ 邮箱生成**授权码** | ✅ 国内直连稳定 |
| `gmail` | `smtp.gmail.com:465`，需两步验证 + 应用专用密码 | ⚠️ 需代理穿透，日常不稳 |
| `smtp` | 自填 host/port | ✅ 通用（GitHub 用户用这个） |
| `none` | 只落 Obsidian，不发信 | ✅ 默认兜底，**没配凭据也不会报错** |

凭据只读环境变量（`~/.hermes/.env` 里的 `MORNING_BREW_SMTP_PASS`），**不写进仓库、不打印、不进聊天**。
自检命令：`python3 ./scripts/send_digest.py --md <早咖啡.md> --dry-run`（不配凭据也能跑通，输出 HTML 预览）。

### ★ 关键设计要求：发件通道必须是配置项，不能写死

**这个项目将来要开源到 GitHub 给别人用**，所以邮件层必须做成可插拔，配置文件里写清"换成你自己的邮箱"：

```yaml
email:
  enabled: true
  provider: gmail        # gmail | smtp | resend | sendgrid | none
  to: "你的收件邮箱@example.com"      # ← 别人用的时候换成自己的
  from: "你的发件人@gmail.com"        # ← Gmail 授权后自动带上；SMTP 方式时自己填
  # smtp 方式才需要下面两项（QQ/163/Gmail 都可用"授权码"而非登录密码）
  # smtp_host: smtp.qq.com
  # smtp_user: you@qq.com
  # 凭据一律存系统凭据库/Hermes 凭据，不写进仓库、不写进聊天
```

**三条硬规矩**（写进开源 README）：
1. **仓库里绝不出现任何真实邮箱、授权码、API key**；只放 `.env.example`。
2. **首次运行必须能"无邮件模式"启动**：`provider=none` 时只输出到 Obsidian，不报错。
3. README 首段就写：**"把 `.env` 里的邮箱换成你自己的"**，并说明 QQ 邮箱需生成授权码、Gmail 需应用专用密码。

**当前状态**：Gmail 待授权 → 先用 `provider: none`（只落 Obsidian），邮件接入后自动生效。
