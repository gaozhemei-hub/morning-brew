# 五道口 AI 早咖啡（Morning Brew）

每天早上把隔夜与昨天的 AI 及相邻行业信息，**按三层专业人设筛一遍**，写成一份进 vault、也能发邮件的晨报，
并**自动维护一张会自己长大的知识网**（术语库 + 人物卡 + 一键关注入口）。

它不只是"信息聚合"，而是**信息聚合 + 认知沉淀**：读一份晨报，等于同时更新一张知识网。

## When to Use

- 用户要"每天早上给我一份前沿简报 / 行业雷达 / 早咖啡"
- 用户想把行业信息**沉淀进 Obsidian**，而不是刷完就忘
- 用户要跟踪行业人物（谁是谁、怎么走到今天、去哪关注他）
- **不要用于**：单篇长文的逐段纪要（那是另一件事）、单纯的股价/行情播报

## Prerequisites

- `terminal` 可用；Python 3.10+，仅标准库 + `urllib`（无重框架）
- 信源配置：`sources/sources.json`（每条带 `verified` 字段记录实测结论与日期）
- 邮箱配置（可选）：复制 `.env.example` → `.env`，把收件人换成用户自己的；`provider=none` 时不发信也不报错
- 海外站点需要代理时：设 `MORNING_BREW_PROXY`（不设则直连，不会报错）
- 输出目录：`MORNING_BREW_VAULT`（默认 `~/morning-brew-output`）

## How to Run

```bash
# 0) 今天是周几决定轮换组：周一/五=AI前沿 周二/六=商业创投 周三=产品工程 周四=半导体 周日=all
python3 scripts/fetch.py --days 2 --rotate AI前沿        # 周一额外加 --weekly
python3 scripts/digest_brief.py --date $(date +%F)       # 给人/模型读的简报
python3 scripts/digest_brief.py --health                 # 只看信源健康
python3 scripts/hotlist.py --per 5                       # 第四块·中文热议
python3 scripts/send_digest.py --md <早咖啡.md> --date <今天>
```

## Procedure

1. **抓取**：`python3 scripts/fetch.py --days 2 --rotate <今日组>`（周一加 `--weekly`）。
   抓完**先看每源的 `new` 字段**。
   *完成标准*：拿到当天 JSON，且知道哪些源失败、哪些只是"今天无新"。
2. **读简报**：`python3 scripts/digest_brief.py`（**不要写内联 python**，cron 环境会拦 heredoc 与 `python3 -c`）。
   *完成标准*：每层都有候选条目（标题 + 摘要 + 链接）。
3. **分级筛选**：从几百条里选 **10–14 条**，按三层组织，每条**结论在前** + `[必须知道]/[值得知道]`：
   - **商业与战略层**（人设：资深一、二级市场投资人）→ 回答"**为什么这个技术能赚钱？谁在买单？**"
   - **技术与前沿层**（人设：有技术背景的 AI 产品经理）→ 回答"**能做什么、不能做什么、下个月可能发生什么**"，
     并**必写一条「衡量方式」**（这件事用什么指标/评测集衡量）
   - **开源与工程层**（人设：工程师）→ "别人怎么把论文变成代码"（每周一次，日常只 1–2 行）
   每条必含：`核心观点`（分点 2–4 条，**不是一句话带过**）→ `为什么现在`（写到二阶影响）→ `名词/人物` → `来源`（链接 + 日期）。
   排序判据：①对 AI 产品岗求职有用 ②对投资判断有用 ③可证伪 ④被多源重复。
   *完成标准*：每条都能读出一句可复述的判断，而不是新闻标题。
4. **写入 vault**：`<vault>/早咖啡-<YYYY-MM>.md` 追加 `## <YYYY-MM-DD>（周几）`（同日已有则更新，不重复）。
   当节末尾附**第四块·今日中文热议**（榜单前几条，**不做解读**，注明"反映共识温度，不是事实"），再附**双链索引**。
5. **知识库维护**（`<vault>/`）：
   - `技术名词库.md`：新术语追加（全称｜大白话｜为什么重要｜出现处），**标题只写短规范名**（供双链锚点）
   - `大佬履历卡.md`：仅当出现**新的公司高管 / 投资人 / 核心研究者**（媒体人、纯转发者不建）才建卡：
     现职｜关键转向｜为什么今天出现（含来源）｜对你的用法；末行必须是**关注入口**（见 skill `person-follow-links`）
   - `关注清单.md`：新名字入表
   *完成标准*：新术语/新人物都已入库，且正文里的双链**点得开**。
6. **语音版（可选）**：`python3 scripts/voice_brief.py --md <早咖啡.md> --date <今天>`。
   把当天章节改写成**收听稿**（结论先行、口头路标、术语半句解释）→ 读法规范化 → 阶跃 TTS 合成 mp3 + 章节时间戳。
   改写稿出现原文没有的数字，该段自动回退规则稿；未配 Key 或合成失败，原因写进 `out/voice-<日期>.json`。
   *完成标准*：要么有 mp3 + 章节目录，要么状态文件写明失败原因。抽检时把读错的词补进 `sources/pronunciation.json`。
7. **发信（可选）**：`python3 scripts/send_digest.py --md <早咖啡.md> --date <今天> --voice out/voice-<今天>.json`。
   语音成功则附 mp3 并在邮件顶部列章节；失败则在顶部写明原因、文字版照发。
   *完成标准*：要么发送成功，要么明确说明失败原因——**不允许静默**。

## 三层信源与轮换

**常驻源每天扫**；**轮换的公众号按星期轮值**（避免同质化源刷屏，同时让每天的产出有主题感）：

| 周几 | 轮换组 | 说明 |
| --- | --- | --- |
| 周一 / 周五 | **AI前沿** | 新智元、机器之心系、PaperWeekly 等 |
| 周二 / 周六 | **商业创投** | 投中、创业邦、经纬、暗涌 等 |
| 周三 | **产品工程** | 人人都是产品经理、各厂技术号 |
| 周四 | **半导体** | 智东西、半导体行业观察 |
| 周日 | **all** | 全扫一遍 |

**信源健康必须区分三类，禁止静默失败**：
✅ 有新增（含条数）｜⚠️ 抓成功但今天无新｜❌ 抓失败/已知缺口（含原因：证书、反爬、需浏览器登录态）

## Pitfalls

- **双链锚点是标题本身**：改了知识库标题，历史链接全会失效。标题只用短规范名，全称写正文里。
- **`enabled:false` 与轮换的判断顺序**：必须先判轮换、再判 enabled；写反了轮换源永远不会启用（踩过）。
- **HTML 源去重键不能砍查询参数**：`?id=1`、`?id=2` 会塌缩成一条，整站只剩 1 条（踩过）。
- **配置文件要对外部环境变量有最终解释权**：持久 shell 里残留的空 `SMTP_PASS` 会盖住 `.env` 里的真授权码。
- **邮件渲染要处理 `>` 引用块与 `---` 分隔线**，否则客户端里原样显示；改完**必须真发一封验证**。
- **X（推特）源依赖本机浏览器登录态**，无人值守环境常失败——如实报告"需浏览器登录态"，不要当作没新闻。
- **"做不到"的结论先去 GitHub 复检**：公众号曾判定"只能自建"，实际有公开实例可用。

## Verification

- [ ] 当天章节已写入，条目 10–14 条，三层都有内容
- [ ] 每条含：判断 + 核心观点分点 + 为什么现在 + 来源链接与日期
- [ ] 技术层每条都有「衡量方式」
- [ ] 正文双链**全部可跳转**（可用脚本校验锚点是否存在于知识库标题）
- [ ] 新人物卡都有「关注入口」，且**低置信度没有假装成主页**
- [ ] 信源健康写明三类状态，没有把"抓失败"写成"今天没新闻"
- [ ] 语音版：有 mp3 与章节目录，或状态文件与邮件里写明了未生成的原因
- [ ] 邮件：发送成功或已说明失败原因
