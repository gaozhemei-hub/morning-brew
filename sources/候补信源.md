# 候补信源（候选池 → 验证 → 升级的中间层）

> **这是什么**：新信源**不直接进正文**。候选源先放这里，按主题分组、标注可用性，**验证通过后才升进正式的三层信源**（`sources/sources.json`）。
> 理由：信源不是越多越好，是**越准**越好；未验证的源直接进正文只会降低信噪比。

## 决策记录（2026-10-12）

- ✅ **A 组：全部启用，但按星期轮换** —— 周一/周五 AI前沿、周二/周六 商业创投、周三 产品工程、周四 半导体、周日全扫。

- ⏸ **B 组 X 大 V：暂不加**。结论：**X 通道不是代码问题，是环境依赖**——`opencli twitter tweets` 需要**本机 Chrome + OpenCLI 扩展在线**（`profile` 能走另一条路，`tweets` 不行）。凌晨 02:43 那次抓到了 6 条 LeCun，后来桥掉了就报 `BROWSER_CONNECT`。**代码侧无法修复**。
  → **要每天有 X，就得让 Chrome 开着且扩展启用**。加更多 X 源只会让"抓失败"那行变长，所以先不加。
- ✅ **C 组热榜：加**，作为「第四块·今日中文热议」。已实现 `scripts/hotlist.py`，取：财联社电报、华尔街见闻、雪球热股、Hacker News、V2EX、少数派、微博热搜、知乎热榜。**只列前几条、不做解读**。
